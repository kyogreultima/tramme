# Taste and finish, step 2: typefaces — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From a description of a character ("condensed grotesque, heavy, for titles") the assistant finds open typefaces, looks at a specimen sheet drawn by the engine's own text path, and brings the chosen ones into the project as font assets at a pinned version, with the guide telling it to pair a display face with a text face and never to leave the system font.

**Architecture:** A catalogue of Fontsource families is generated by a script (list endpoint plus the axes of the variable ones, derived tags, and a hand-written overlay of character tags for a few hundred well-known families), served as a static file of the editor and loaded lazily. Two tools of the editor's vocabulary: `typefaces` (search, text list, specimen sheet) and `typeface-use` (fetch the files from jsDelivr at one pinned version, write them under `assets/fonts/` with a record, add the font assets). Search, file naming and sheet layout are pure functions; only drawing and fetching touch the browser.

**Tech Stack:** TypeScript (Node 24 type stripping, vitest), `apps/editor`, `scripts/typefaces`, Fontsource (`api.fontsource.org`, `cdn.jsdelivr.net/fontsource`).

**Spec:** [docs/superpowers/specs/2026-10-29-taste-and-finish-design.md](../specs/2026-10-29-taste-and-finish-design.md), section "2. Typefaces". Step 1's plan is [here](2026-10-29-taste-and-finish-step1-make-what-exists-work.md); this plan does not depend on its unmeasured results. Steps 3 to 8 get their own plans.

## Global Constraints

- No typeface ships in the repo (the user's decision when `fonts/` was removed): only metadata does. Font files are fetched at a pinned version and copied into the project, as the kits already do (`BUILTIN_KITS` in `apps/editor/src/recipes.ts`).
- Rights: only families under OFL-1.1, Apache-2.0, MIT, CC0-1.0, Unlicense or UFL-1.0 are in the catalogue; the licence is written in the record beside the files and said in the tool's text.
- Everything made is a file of the project with its record (`docs/generation-roadmap.md`); the project stays self-contained and reproducible offline once the fonts are in.
- One mechanism for the assistant and the user: both capabilities are tools of the vocabulary (`use_tool` and the `/` menu); the document changes only through returned operations.
- New user-visible strings go through `t()` / the content translation (English key in `apps/editor/src/i18n/en.json`, French in `fr.json`; `apps/editor/test/i18n.test.ts` fails otherwise); French text addresses the user as "vous". No em dash in user-visible text.
- Shared modules, no copies: reuse `canvas()` of `apps/editor/src/perception.ts` for drawing and the `font` asset shape of `kit`; audit your own diff for duplication before handing over (user's standing rule).
- Nothing is tuned on one video; `bench/briefs.json` test briefs stay unseen.
- Commits carry no Claude attribution; one commit per task.
- Shell edits of files holding backslashes lose them in this environment: use the Edit or Write tool for any code containing `\`.

## Review Focus

- A query with no match, or with words the vocabulary does not know ("quirky"): the answer says so and gives the closest families by name or tag, never an empty sheet.
- Text with accents (French), Cyrillic, Greek, Arabic, Hebrew or CJK: only families whose subsets cover it come back; for a script almost none cover, the answer says so.
- A font file that fails to download (offline, 404): `typeface-use` reports it and changes nothing (no half-written files, no orphan asset); in a sheet, the cell says it could not load and the others are drawn.
- The same `typeface-use` twice, or a family already in the project: no duplicate asset ids, no second copy of the files.
- A variable family: one file and a weight range; a static family: only the requested weights are fetched.
- The catalogue file unreachable (offline dev server): a clear error naming the file, not a hang.
- A family name with spaces, digits or a plus sign (`Noto Sans`, `M PLUS 1`, `Playwrite DE Grund`): ids and file names stay valid.

### Task 2: Search by character

**Files:**
- Create: `apps/editor/src/typefaces/search.ts`
- Test: `apps/editor/test/typefaces.test.ts`

**Interfaces:**
- Consumes: `Catalogue`, `Typeface` (Task 1).
- Produces: `scriptsOf(text: string): string[]` (the Fontsource subsets a text needs: `latin` for Latin letters and digits, `latin-ext` for letters beyond Latin-1 that need it, `vietnamese`, `cyrillic`, `greek`, `arabic`, `hebrew`, `devanagari`, `thai`, `japanese`, `korean`, `chinese-simplified`, `chinese-traditional`); `searchTypefaces(catalogue: Catalogue, query: string, opts?: { text?: string; category?: Typeface['category']; count?: number }): { found: { font: Typeface; score: number; why: string[] }[]; unknown: string[]; closest: boolean }`.

- [ ] **Step 1: Write the failing tests** over the generated catalogue (the real data, not a fixture):
  - `scriptsOf('Prix : 40 €')` is `['latin']`; `scriptsOf('Évasion')` is `['latin']`; `scriptsOf('Привет')` holds `cyrillic`; `scriptsOf('مرحبا')` holds `arabic`; `scriptsOf('שלום')` holds `hebrew`; `scriptsOf('こんにちは')` holds `japanese`.
  - `searchTypefaces(cat, 'condensed grotesque heavy titles')`: at most 6 found by default, each with `condensed` among its tags, the first with `heavy`; `why` names the matched tags.
  - `'elegant serif for a quote'`: every font has `serif` or `elegant`; none is `monospace`.
  - `'handwritten marker'` gives fonts of category `handwriting`.
  - `'quirky zebra'` returns `unknown: ['quirky', 'zebra']`, `closest: true`, and still at least one found (a fallback on the category word or the most used family), never an empty list.
  - With `text: 'Привет'` every found font has `cyrillic` in its subsets; with `text: 'مرحبا'` every one has `arabic`; with a script no family covers the result is empty and `closest` is false.
  - Words are case and plural insensitive (`Titles`, `HEAVY`), and the synonyms hold: `thick`, `black`, `fat` mean `heavy`; `narrow`, `compressed` mean `condensed`; `monospaced`, `code` mean `mono`; `script`, `cursive` mean `handwritten`; `title(s)`, `headline(s)`, `heading(s)` mean `for: title`; `body`, `paragraph` mean `for: text`.
  - Ranking: a family of the overlay (described by hand) outranks a family matched by derived tags alone, for the same match count.
- [ ] **Step 2: Run** — expected: FAIL.
- [ ] **Step 3: Implement** `scriptsOf` (by Unicode ranges) and `searchTypefaces`: normalise the query to words, map synonyms to `TAGS` / categories / `for` values, drop filler words; a font scores one per matched tag, `for` or category, two more when the family name contains a word, one more when it has an overlay entry; candidates must cover `scriptsOf(opts.text)` in their subsets; ties break by overlay first, then fewer weights missing for the asked character, then name. Words that map to nothing go in `unknown`; with no scored font, fall back to name-substring matches and then to the overlay families of the closest category with `closest: true`.
- [ ] **Step 4: Run** — expected: PASS.
